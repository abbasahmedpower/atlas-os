# Structured adversarial review
Run distinct *perspectives* (not a claim of independent agents): Architect checks requirements & coupling; Skeptic searches counterexample; Security reviewer checks trust boundaries, input limits & abuse potential; Test engineer designs negative, property-based and mutation tests; Educator checks whether learner can transfer understanding.
Produce 5 review findings sorted by severity, evidence and remediation. Do not fabricate external reviewers or tool execution.
Every major claim needs an argument, evidence, likely failure mode, and disconfirming observation. Required: one red-team question "What would make this answer confidently wrong?" and a green-team detection/mitigation option.
